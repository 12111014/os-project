Reasoning:
Memory filesystem pattern with 7 well-separated modules. Single global mutex on inode table is the simplest correct approach for a memory-backed FS where all data is in RAM — fine-grained locking adds complexity without benefit since there is no disk I/O to parallelize. GLib hash table chosen for inode table because it provides efficient O(1) lookup, resize, and iteration without reinventing hash maps. Directory entries use both linked list (for ordered readdir output) and hash map (for fast lookup) — this is a standard tradeoff. File data uses simple malloc/realloc byte buffers with 4KB growth increments to match the specified block size. Permissions are separated into their own module to keep fuse_ops thin. Path resolution is isolated so all operations get consistent traversal behavior. fsync is a no-op because there is no persistent storage. Explicitly excluding symlinks, hardlinks, xattrs, and journaling as the IR specifies these are disabled.
